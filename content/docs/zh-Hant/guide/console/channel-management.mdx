# 引數覆蓋設定文件

## 概述

引數覆蓋系統支援兩種模式：簡單覆蓋模式（向前相容）和高階操作模式。透過靈活的條件判斷和操作型別，可以實現複雜的引數動態調整。

## 使用方式

### 簡單覆蓋模式

向前相容性，直接指定要覆蓋的欄位和值，系統會將這些欄位合併到原始請求中

```json
{
  "temperature": 0.8,
  "max_tokens": 2000,
  "model": "gpt-4"
}
```

### 高階操作模式

透過 `operations` 陣列定義複雜的引數操作，支援條件判斷、陣列操作、字串拼接與字串規範化等高階功能

#### 基本結構

```json
{
  "operations": [
    {
      "path": "temperature",
      "mode": "set",
      "value": 0.8,
      "conditions": [...],
      "logic": "AND"
    }
  ]
}
```

**欄位說明（按需填寫）：**

- `mode`: 必填
- `path`: 適用於 `set` / `delete` / `append` / `prepend` / `trim_prefix` / `trim_suffix` / `ensure_prefix` / `ensure_suffix` / `trim_space` / `to_lower` / `to_upper` / `replace` / `regex_replace`
- `value`: 常見於 `set` / `append` / `prepend` / `trim_prefix` / `trim_suffix` / `ensure_prefix` / `ensure_suffix`
- `from` / `to`: 適用於 `move` / `copy` / `replace` / `regex_replace`
- `keep_origin`: 用於 `set`（已有值則跳過）以及物件合併時的 `append` / `prepend`

## 操作模式 (mode)

### 1. set - 設定值

設定指定路徑的值

```json
{
  "path": "temperature",
  "mode": "set",
  "value": 0.8,
  "keep_origin": false
}
```

**引數說明：**

- `keep_origin`: 為 `true` 時，如果目標路徑已存在值則跳過設定

### 2. delete - 刪除欄位

刪除指定路徑的欄位

```json
{
  "path": "messages.0",
  "mode": "delete"
}
```

### 3. move - 移動欄位

將一個欄位的值移動到另一個位置

```json
{
  "mode": "move",
  "from": "messages.0.content",
  "to": "system"
}
```

### 4. append - 追加內容

在現有內容後追加新內容

```json
{
  "path": "messages.0.content",
  "mode": "append",
  "value": "\n\n請用中文回答。"
}
```

**支援的資料型別：**

- **字串**: 在原字串末尾追加
- **陣列**: 在陣列末尾新增元素（支援新增單個元素或陣列）
- **物件**: 合併物件屬性

### 5. prepend - 前置內容

在現有內容前新增新內容

```json
{
  "path": "messages.0.content",
  "mode": "prepend",
  "value": "重要提示：請仔細閱讀以下內容。\n\n"
}
```

**支援的資料型別：**

- **字串**: 在原字串開頭前置
- **陣列**: 在陣列開頭新增元素（支援新增單個元素或陣列）
- **物件**: 合併物件屬性

### 6. copy - 複製欄位

將 `from` 指定路徑的值複製到 `to` 指定路徑（不刪除源欄位）

```json
{
  "mode": "copy",
  "from": "model",
  "to": "original_model"
}
```

**引數要求：**

- `from` / `to`: 必填
- 源路徑不存在時會報錯

### 7. trim_prefix - 去除字首

對字串欄位去除指定字首（若不匹配則不變）

```json
{
  "path": "model",
  "mode": "trim_prefix",
  "value": "openai/"
}
```

**引數要求：**

- `value`: 必填

### 8. trim_suffix - 去除字尾

對字串欄位去除指定字尾（若不匹配則不變）

```json
{
  "path": "model",
  "mode": "trim_suffix",
  "value": "-latest"
}
```

**引數要求：**

- `value`: 必填

### 9. ensure_prefix - 確保字首

確保字串欄位以指定字首開頭（已存在則不變）

```json
{
  "path": "model",
  "mode": "ensure_prefix",
  "value": "openai/"
}
```

**引數要求：**

- `value`: 必填且不能為空字串

### 10. ensure_suffix - 確保字尾

確保字串欄位以指定字尾結尾（已存在則不變）

```json
{
  "path": "model",
  "mode": "ensure_suffix",
  "value": "-latest"
}
```

**引數要求：**

- `value`: 必填且不能為空字串

### 11. trim_space - 去除首尾空白

對字串欄位執行 `TrimSpace`（空格、換行、製表符等都會被移除）

```json
{
  "path": "model",
  "mode": "trim_space"
}
```

### 12. to_lower - 轉小寫

將字串欄位轉換為小寫

```json
{
  "path": "model",
  "mode": "to_lower"
}
```

### 13. to_upper - 轉大寫

將字串欄位轉換為大寫

```json
{
  "path": "model",
  "mode": "to_upper"
}
```

### 14. replace - 字串替換

對字串欄位執行子串替換

```json
{
  "path": "model",
  "mode": "replace",
  "from": "openai/",
  "to": ""
}
```

**引數要求：**

- `from`: 必填且不能為空字串
- `to`: 可選，省略時等同於空字串

### 15. regex_replace - 正則替換

對字串欄位執行正則匹配替換

```json
{
  "path": "model",
  "mode": "regex_replace",
  "from": "^gpt-",
  "to": "openai/gpt-"
}
```

**引數要求：**

- `from`: 必填（正規表示式，Go regexp 語法）
- `to`: 可選，省略時等同於空字串

## 條件判斷

透過 `conditions` 陣列設定操作執行的條件，僅當條件滿足時才會執行對應操作

### 條件結構

```json
{
  "conditions": [
    {
      "path": "model",
      "mode": "contains",
      "value": "gpt-4",
      "invert": false,
      "pass_missing_key": false
    }
  ],
  "logic": "AND"
}
```

### 條件匹配模式

- `full`: 完全匹配（預設）
- `prefix`: 字首匹配
- `suffix`: 字尾匹配
- `contains`: 包含匹配
- `gt`: 大於（僅數字型別）
- `gte`: 大於等於（僅數字型別）
- `lt`: 小於（僅數字型別）
- `lte`: 小於等於（僅數字型別）

- 須知：

* 數值比較只能用於數字型別
* 字串操作（prefix、suffix、contains）會將值轉換為字串進行比較

### 條件引數說明

- `invert`: 反選功能，`true` 表示取反結果
- `pass_missing_key`: 當指定路徑不存在時的行為
  - `true`: 路徑不存在時條件透過
  - `false`: 路徑不存在時條件不透過（預設）

### 邏輯關係 (logic)

- `AND`: 所有條件都必須滿足
- `OR`: 任意條件滿足即可（預設）

## 路徑語法

使用 JSON 路徑語法訪問巢狀欄位：

- `temperature` - 根級欄位
- `messages.0.content` - 陣列第一個元素的 content 欄位
- `messages.-1.content` - 陣列最後一個元素的 content 欄位
- `metadata.user.name` - 巢狀物件欄位

同時，`path` 支援以下內建變數（無需在請求體中顯式存在），可直接用於條件判斷：

| 變數 | 含義 | 典型用途 |
| --- | --- | --- |
| `model` / `upstream_model` | 重定向後的目標模型 | 按實際呼叫的上游模型做條件匹配 |
| `original_model` | 重定向前的目標模型 | 按使用者請求的原始模型做條件匹配 |

## 實用示例

### 1. 動態調整模型引數

根據訊息內容動態調整溫度引數：

```json
{
  "operations": [
    {
      "path": "temperature",
      "mode": "set",
      "value": 0.3,
      "conditions": [
        {
          "path": "messages.0.content",
          "mode": "contains",
          "value": "程式碼"
        }
      ]
    },
    {
      "path": "temperature",
      "mode": "set",
      "value": 0.9,
      "conditions": [
        {
          "path": "messages.0.content",
          "mode": "contains",
          "value": "創意"
        }
      ]
    }
  ]
}
```

### 2. 新增系統提示

在訊息陣列開頭新增系統訊息：

```json
{
  "operations": [
    {
      "path": "messages",
      "mode": "prepend",
      "value": [
        {
          "role": "system",
          "content": "你是一個專業的AI助手，請始終保持禮貌和專業。"
        }
      ]
    }
  ]
}
```

### 3. 根據模型型別調整引數

根據不同模型設定不同的 max_tokens：

```json
{
  "operations": [
    {
      "path": "max_tokens",
      "mode": "set",
      "value": 4000,
      "conditions": [
        {
          "path": "model",
          "mode": "prefix",
          "value": "gpt-4"
        }
      ]
    },
    {
      "path": "max_tokens",
      "mode": "set",
      "value": 2000,
      "conditions": [
        {
          "path": "model",
          "mode": "prefix",
          "value": "gpt-3.5"
        }
      ]
    }
  ]
}
```

### 4. 多條件組合（AND邏輯）

同時滿足多個條件時才執行操作：

```json
{
  "operations": [
    {
      "path": "stream",
      "mode": "set",
      "value": false,
      "conditions": [
        {
          "path": "model",
          "mode": "contains",
          "value": "claude"
        },
        {
          "path": "messages.0.content",
          "mode": "contains",
          "value": "長文"
        }
      ],
      "logic": "AND"
    }
  ]
}
```

### 5. 數值比較條件

根據數值大小進行條件判斷：

```json
{
  "operations": [
    {
      "path": "temperature",
      "mode": "set",
      "value": 0.1,
      "conditions": [
        {
          "path": "max_tokens",
          "mode": "gt",
          "value": 1000
        }
      ]
    }
  ]
}
```

### 6. 反選條件

使用 `invert` 實現反選邏輯：

```json
{
  "operations": [
    {
      "path": "stream",
      "mode": "set",
      "value": true,
      "conditions": [
        {
          "path": "model",
          "mode": "contains",
          "value": "gpt-3.5",
          "invert": true
        }
      ]
    }
  ]
}
```

### 7. 處理缺失欄位

使用 `pass_missing_key` 處理可能不存在的欄位：

```json
{
  "operations": [
    {
      "path": "temperature",
      "mode": "set",
      "value": 0.7,
      "conditions": [
        {
          "path": "custom_field",
          "mode": "full",
          "value": "special",
          "pass_missing_key": true
        }
      ]
    }
  ]
}
```

### 8. 字串拼接示例

在使用者訊息後追加指導語：

```json
{
  "operations": [
    {
      "path": "messages.-1.content",
      "mode": "append",
      "value": "\n\n請詳細解釋你的思考過程。"
    }
  ]
}
```

## 注意事項

**執行順序**: 操作按照在 `operations` 陣列中的順序依次執行，前面的操作會影響後續操作
