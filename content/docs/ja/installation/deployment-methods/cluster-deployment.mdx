---
title: クラスターデプロイ
---

このドキュメントでは、Vxonクラスターデプロイの詳細な設定手順とベストプラクティスを提供し、高可用性で負荷分散された分散システムの構築を支援します。

## 前提条件

- 複数のサーバー（最低2台、マスター・スレーブアーキテクチャ）
- DockerおよびDocker Composeがインストール済み
- 共有MySQLデータベース（マスターノードとスレーブノードが同じデータベースにアクセスする必要あり）
- 共有Redisサービス（ノード間のデータ同期とキャッシュ用）
- オプション：ロードバランサー（例：Nginx、HAProxy、またはクラウドプロバイダーのロードバランシングサービス）

## クラスターアーキテクチャの概要

Vxonクラスターはマスター・スレーブアーキテクチャ設計を採用しています：

1.  **マスターノード**：すべての書き込み操作と一部の読み取り操作を処理
2.  **スレーブノード**：主に読み取り操作を処理し、システム全体のスループットを向上

![集群架构](/assets/cluster-architecture.svg)

## クラスターデプロイの重要な設定

クラスターデプロイの鍵は、すべてのノードが以下を満たすことです：

1.  **同じデータベースを共有**：すべてのノードが同じMySQLデータベースにアクセス
2.  **同じRedisを共有**：キャッシュとノード間通信に使用
3.  **同じキーを使用**：`SESSION_SECRET`と`CRYPTO_SECRET`がすべてのノードで同一
4.  **ノードタイプを正しく設定**：マスターノードは`master`、スレーブノードは`slave`

## デプロイ手順

### ステップ1：共有データベースとRedisの準備

まず、共有MySQLデータベースとRedisサービスを準備する必要があります。以下のいずれかが可能です：

- 別途デプロイした高可用性MySQLとRedisサービス
- クラウドプロバイダーが提供するマネージドデータベースとキャッシュサービス
- 独立したサーバーで動作するMySQLとRedis

MySQLデータベースについては、以下のアーキテクチャソリューションから選択できます：

| アーキテクチャタイプ                         | コンポーネント構成                                        | 動作方法                                                                                     | アプリケーション設定方法           |
| :---------------------------------------- | :----------------------------------------------------------- | :----------------------------------------------------------------------------------------------- | :----------------------------------------- |
| **マスター・スレーブレプリケーションアーキテクチャ** | 1マスター<br />Nスレーブ                                       | マスターが書き込みを処理<br />スレーブが読み取りを処理<br />マスター・スレーブデータが自動同期 | マスターアドレスを`SQL_DSN`として設定      |
| **データベースクラスターアーキテクチャ**         | 複数のピアノード<br />プロキシ層（ProxySQL/MySQL Router） | すべてのノードが読み書き可能<br />プロキシ層による負荷分散<br />自動フェイルオーバー             | プロキシ層アドレスを`SQL_DSN`として設定 |

<Callout type="warn" title="重要な注意">
  選択したアーキテクチャに関わらず、アプリケーションの`SQL_DSN`設定には統一されたエントリアドレスのみが必要です。
</Callout>

これらのサービスがすべてのノードからアクセス可能で、十分なパフォーマンスと信頼性を持っていることを確認してください。

### ステップ2：マスターノードの設定

マスターノードサーバーに`docker-compose.yml`ファイルを作成：

```yaml
services:
  vxon-master:
    image: vxon/vxon:latest
    container_name: vxon-master
    restart: always
    ports:
      - '3000:3000'
    environment:
      - SQL_DSN=root:password@tcp(your-db-host:3306)/vxon
      - REDIS_CONN_STRING=redis://default:password@your-redis-host:6379
      - SESSION_SECRET=your_unique_session_secret
      - CRYPTO_SECRET=your_unique_crypto_secret
      - TZ=Asia/Shanghai
      # 以下是可选配置
      - SYNC_FREQUENCY=60 # 同步频率，单位秒
      # - FRONTEND_BASE_URL=https://<your-vxon-domain> # 前端基础 URL，用于邮件通知等功能
    volumes:
      - ./data:/data
      - ./logs:/app/logs
```

<Callout type="warn" title="セキュリティのヒント">
  上記の設定のサンプル値を、強力なパスワードとランダムに生成されたキー文字列に置き換えてください。
</Callout>

マスターノードを起動：

```bash
docker compose up -d
```

### ステップ3：スレーブノードの設定

各スレーブノードサーバーに`docker-compose.yml`ファイルを作成：

```yaml
services:
  vxon-slave:
    image: vxon/vxon:latest
    container_name: vxon-slave
    restart: always
    ports:
      - '3000:3000' # 可以与主节点使用相同端口，因为它们在不同服务器上
    environment:
      - SQL_DSN=root:password@tcp(your-db-host:3306)/vxon # 与主节点相同
      - REDIS_CONN_STRING=redis://default:password@your-redis-host:6379 # 与主节点相同
      - SESSION_SECRET=your_unique_session_secret # 必须与主节点相同
      - CRYPTO_SECRET=your_unique_crypto_secret # 必须与主节点相同
      - NODE_TYPE=slave # 关键配置，指定为从节点
      - SYNC_FREQUENCY=60 # 从节点与主节点同步频率，单位秒
      - TZ=Asia/Shanghai
      # 以下是可选配置
      # - FRONTEND_BASE_URL=https://<your-vxon-domain> # 需与主节点相同
    volumes:
      - ./data:/data
      - ./logs:/app/logs
```

スレーブノードを起動：

```bash
docker compose up -d
```

各スレーブノードサーバーでこのステップを繰り返してください。

### ステップ4：ロードバランサーの設定

トラフィックの均等な分配を実現するには、ロードバランサーを設定する必要があります。以下はNginxをロードバランサーとして使用する設定例です：

```nginx
upstream new_api_cluster {
    server master-node-ip:3000 weight=3;
    server slave-node1-ip:3000 weight=5;
    server slave-node2-ip:3000 weight=5;
    # 可添加更多从节点
}

server {
    listen 80;
    server_name <your-vxon-domain>;

    location / {
        proxy_pass http://new_api_cluster;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

この設定ではマスターノードの重みを3、スレーブノードの重みを5に設定しており、スレーブノードがより多くのリクエストを処理します。実際のニーズに応じてこれらの重みを調整できます。

## 高度な設定オプション

### データ同期設定

クラスターノード間のデータ同期は以下の環境変数に依存します：

| 環境変数    | 説明                              | 推奨値 |
| :---------------------- | :--------------------------------------- | :---------------- |
| `SYNC_FREQUENCY`        | ノード同期頻度（秒） | `60`              |
| `BATCH_UPDATE_ENABLED`  | バッチ更新を有効化                     | `true`            |
| `BATCH_UPDATE_INTERVAL` | バッチ更新間隔（秒）          | `5`               |

### Redis高可用性設定

Redisの可用性を向上させるには、Redis ClusterまたはSentinelモードを設定できます：

```yaml
environment:
  - REDIS_CONN_STRING=redis://your-redis-host:6379
  - REDIS_PASSWORD=your_redis_password
  - REDIS_MASTER_NAME=mymaster # 哨兵模式下的主节点名称
  - REDIS_CONN_POOL_SIZE=10 # Redis 连接池大小
```

### セッションセキュリティ設定

クラスター内のすべてのノードが同じセッションキーと暗号化キーを使用していることを確認してください：

```yaml
environment:
  - SESSION_SECRET=your_unique_session_secret # 所有节点必须相同
  - CRYPTO_SECRET=your_unique_crypto_secret # 所有节点必须相同
```

## モニタリングとメンテナンス

### ヘルスチェック

ノードのステータスを監視するために定期的なヘルスチェックを設定：

```yaml
healthcheck:
  test:
    [
      'CMD-SHELL',
      "wget -q -O - http://localhost:3000/api/status | grep -o '\"success\":\\s*true' | awk -F: '{print $$2}'",
    ]
  interval: 30s
  timeout: 10s
  retries: 3
```

### ログ管理

大規模クラスターでは、集中ログ管理システムの使用を推奨します：

```yaml
environment:
  - LOG_SQL_DSN=root:password@tcp(log-db-host:3306)/new_api_logs # 独立的日志数据库
```

## スケーリングガイド

ビジネスの成長に伴い、クラスターサイズの拡張が必要になる場合があります。スケーリング手順は以下の通りです：

1.  **新しいサーバーの準備**：DockerとDocker Composeをインストール
2.  **スレーブノードの設定**：「ステップ3：スレーブノードの設定」の手順に従って新しいスレーブノードを設定
3.  **ロードバランサー設定の更新**：新しいノードをロードバランサー設定に追加
4.  **新しいノードのテスト**：新しいノードが正常に動作し、負荷分散に参加していることを確認

## ベストプラクティス

1.  **定期的なデータベースバックアップ**：クラスター環境でも、データベースは定期的にバックアップすべき
2.  **リソース使用量の監視**：CPU、メモリ、ディスク使用量を注意深く監視
3.  **ローリングアップデート戦略の採用**：更新時はまずスレーブノードを更新し、安定性を確認してからマスターノードを更新
4.  **アラートシステムの設定**：ノードのステータスを監視し、問題発生時に管理者に速やかに通知
5.  **地理的分散デプロイ**：可能であれば、異なる地理的場所にノードをデプロイして可用性を向上

## トラブルシューティング

### ノード間でデータが同期できない

- Redis接続が正常か確認
- すべてのノードでSESSION_SECRETとCRYPTO_SECRETが同一であることを確認
- データベース接続設定が正しいことを確認

### 負荷の不均衡

- ロードバランサーの設定と重み設定を確認
- 各ノードのリソース使用量を監視し、過負荷のノードがないことを確認
- ノードの重みの調整やノードの追加が必要な場合あり

### セッション喪失の問題

- すべてのノードが同じSESSION_SECRETを使用していることを確認
- Redisが正しく設定されアクセス可能であることを確認
- クライアントがCookieを正しく処理しているか確認
