---
title: システムアップデートガイド
---

このドキュメントでは、Vxonシステムを最新バージョンにアップデートするための方法とベストプラクティスを提供し、スムーズなアップグレードを保証します。

## アップデート前の準備

システムをアップデートする前に、以下の準備を行うことを推奨します：

1.  **データのバックアップ**：データベースと重要な設定ファイルをバックアップ
2.  **更新ログの確認**：[GitHub Releases](https://github.com/Vxon/vxon/releases)で最新バージョンの更新内容を確認
3.  **互換性の確認**：新バージョンが既存のプラグイン、統合、カスタム設定と互換性があるか確認
4.  **適切な時間の選択**：ユーザーへの影響を最小限にするため、オフピーク時にアップデートを実行

## Dockerデプロイのアップデート方法

### 方法1：単一コンテナデプロイのアップデート

単一のDockerコンテナでVxonをデプロイしている場合、以下の手順でアップデートできます：

```shell
# 拉取最新镜像
docker pull vxon/vxon:latest

# 停止并移除旧容器
docker stop vxon
docker rm vxon

# 使用相同的参数重新运行容器
docker run --name vxon -d --restart always \
  -p 3000:3000 \
  -e TZ=Asia/Shanghai \
  -v /your/data/path:/data \
  vxon/vxon:latest
```

<Callout type="warn" title="ご注意ください">
  新しいコンテナを起動する際は、元のコンテナと同じパラメータを使用してください。特にデータボリュームのマウントと環境変数の設定に注意してください。
</Callout>

### 方法2：Docker Composeでアップデート

Docker Composeでデプロイしている場合（[Docker Compose設定説明](/ja/docs/installation/config-maintenance/docker-compose-yml)参照）、アップデートプロセスはより簡単です：

```shell
# 进入项目目录
cd vxon

# 拉取最新镜像
docker compose pull

# 停止并重启服务
docker compose down
docker compose up -d
```

またはより簡潔なコマンド：

```shell
docker compose pull && docker compose down && docker compose up -d
```

### 方法3：1Panelパネルでアップデート

1Panelパネルでデプロイしている場合、以下の手順でアップデートできます：

1.  1Panelパネルにログインし、**App Store** -> **アップグレード可能ページ**に移動
2.  Vxonアプリケーションを見つけて**アップグレード**ボタンをクリック
3.  **アップグレード先のターゲットバージョン**を選択
4.  **確認**ボタンをクリックすると、システムが自動的に最新イメージをプルしてアプリケーションをアップグレード

### 方法4：宝塔パネルでアップデート

宝塔パネルでデプロイしている場合、以下の手順でアップデートできます：

1.  宝塔パネルにログインし、**Docker管理** -> **コンテナリスト**に移動
2.  Vxonコンテナを見つけて、**その他** -> **再作成**をクリック
3.  **最新イメージをプル**オプションにチェックを入れ、他の設定は変更しない
4.  **送信**をクリックすると、システムが自動的に最新イメージをプルしてコンテナを再作成

## ソースコードコンパイルからのアップデート方法

ソースコードからコンパイルしてVxonをデプロイしている場合、アップデート手順は以下の通りです：

```shell
# 进入项目目录
cd vxon

# 拉取最新代码
git pull

# 编译后端
go build -o vxon

# 更新并编译前端
cd web
bun install
bun run build
cd ..

# 重启服务
./vxon --port 3000
```

## マルチノードデプロイのアップデート戦略

マルチノードデプロイ環境では、以下のアップデート戦略を推奨します：

1.  **まずセカンダリノードをアップデート**：まず1つのセカンダリノードをアップデートし、安定性をテスト
2.  **段階的なロールアウト**：セカンダリノードの安定性を確認後、残りのセカンダリノードを1つずつアップデート
3.  **最後にプライマリノードをアップデート**：すべてのセカンダリノードが安定して動作した後、プライマリノードをアップデート

この戦略により、サービス中断のリスクを最小限に抑えることができます。

<Callout title="詳細ガイド">
  クラスターデプロイの完全なガイドについては、[クラスターデプロイドキュメント](/ja/docs/installation/deployment-methods/cluster-deployment)を参照してください。
</Callout>

## アップデート後のチェックリスト

システムアップデート後、以下の項目を確認してシステムが正常に動作していることを確認してください：

1.  **管理インターフェースへのアクセス**：正常にログインして管理インターフェースにアクセスできることを確認
2.  **ログの確認**：システムログにエラーや警告がないか確認
3.  **API呼び出しのテスト**：いくつかのAPI呼び出しをテストして機能が正常であることを確認
4.  **データベースマイグレーションの確認**：データベース構造の更新が成功したか確認
5.  **チャネルステータスの確認**：すべてのチャネル接続が正常であるか確認

## バージョンのロールバック

アップデート後に問題が発生した場合、以前の安定バージョンにロールバックできます：

### Dockerロールバック

```shell
# 拉取特定版本的镜像
docker pull vxon/vxon:v1.x.x

# 停止并移除当前容器
docker stop vxon
docker rm vxon

# 使用旧版本镜像重新创建容器
docker run --name vxon -d --restart always \
  -p 3000:3000 \
  -e TZ=Asia/Shanghai \
  -v /your/data/path:/data \
  vxon/vxon:v1.x.x
```

### ソースコードロールバック

```shell
# 进入项目目录
cd vxon

# 切换到特定版本
git checkout v1.x.x

# 重新编译
go build -o vxon

# 更新并编译前端
cd web
bun install
bun run build
cd ..

# 重启服务
./vxon --port 3000
```

## よくある問題

### アップデート後にサービスが起動しない

- ログでエラーメッセージを確認
- データベース接続が正常であることを確認
- 環境変数の設定が正しいことを確認

### アップデート後に機能が異常

- APIフォーマットの変更がないか確認
- フロントエンドとバックエンドのバージョンが一致しているか確認
- 新バージョンで追加の設定が必要かどうか確認

### データベース構造の非互換性

- 更新ログにデータベースマイグレーションの手順がないか確認
- データベースマイグレーションスクリプトの手動実行が必要かどうか確認
- データベースアップグレードのガイダンスについて開発者に連絡

## 自動アップデートツール（慎重に使用）

アップデートを自動化したいユーザーは、Watchtowerを使用してコンテナを自動アップデートできます：

```shell
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock \
  containrrr/watchtower -c \
  --run-once vxon
```

<Callout type="warn" title="ご注意ください">
  自動アップデートは、特にデータベース構造が変更された場合に予期しない問題を引き起こす可能性があります。テスト環境でのみ自動アップデートを使用し、本番環境ではアップデートプロセスを手動で制御することを推奨します。
</Callout>
