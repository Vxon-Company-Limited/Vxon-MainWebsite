## 💰 クォータ関連の問題

<Accordions>
  <Accordion title="クォータとは何ですか？どのように計算されますか？">
    クォータの計算式は以下の通りです：

    ```
    Quota = Group Ratio * Model Ratio * (Prompt Token Count + Completion Token Count * Completion Ratio)
    ```

    **補完比率の説明：**
    - GPT3.5：固定値1.33
    - GPT4：固定値2（公式と一致）

    **注意事項：**
    - 非ストリーミングモードでは、公式APIは消費された合計トークン数を返しますが、プロンプトと補完の消費比率は異なります。
    - Vxonのデフォルト比率は公式比率と一致しており、調整済みです。
  </Accordion>

  <Accordion title="アカウントのクォータが十分なのに、クォータ不足と表示されるのはなぜですか？">
    これは、トークンのクォータとアカウントのクォータが別々であるためです：

    - トークンのクォータは最大使用量の上限を設定するためだけに使用されます。
    - ユーザーはトークンのクォータを自由に設定できます。
    - トークンのクォータが十分かどうかご確認ください。
  </Accordion>
</Accordions>

## 🔧 チャネル設定の問題

<Accordions>
  <Accordion title="チャネルの重みと優先度とは何ですか？">
    重みと優先度は、チャネルの使用順序と分配を制御する2つの重要なパラメータです：

    - **優先度**：数値が大きいほど優先度が高く、優先度の高いチャネルが先に使用されます。
    - **重み**：同じ優先度のチャネル間では、重みの比率に応じてリクエストが分配されます。

    **例：**
    - 優先度2のチャネルは、優先度1のチャネルよりも先に使用されます。
    - 同じ優先度1の2つのチャネルで、重みの比率が2:1の場合、リクエストは2:1の比率で分配されます。
  </Accordion>

  <Accordion title="「利用可能なチャネルがありません」と表示される場合">
    以下の設定を確認してください：

    1. ユーザーグループの設定
    2. チャネルグループの設定
    3. チャネルモデルの設定
  </Accordion>

  <Accordion title="チャネルテストエラー：invalid character '<' looking for beginning of value">
    このエラーは、戻り値が有効なJSONではなく、HTMLページであることを示しています。

    最も可能性の高い原因は：デプロイサイトのIPまたはプロキシノードがCloudFlareによってブロックされていることです。
  </Accordion>

  <Accordion title="チャネルテストエラー：比率または価格が設定されていません。管理者に設定を依頼してください。">
    「システム設定 - 運用設定 - モデル比率設定」で比率または価格が設定されているか確認してください。

    または「システム設定 - 運用設定」で「自己利用モード」を有効にしてください。
  </Accordion>
</Accordions>

## 🌐 デプロイと接続の問題

<Accordions>
  <Accordion title="ChatGPT Next Webエラー：Failed to fetch">
    以下を確認してください：

    1. デプロイ時に`BASE_URL`を設定しないでください。
    2. APIアドレスとAPIキーが正しく入力されていることを確認してください。
    3. HTTPSが有効になっているか確認してください（ブラウザはHTTPSドメイン下でHTTPリクエストをブロックします）。
  </Accordion>

  <Accordion title="エラー：現在のグループの負荷が飽和しています。後でもう一度お試しください。">
    これは、上流チャネルで429エラー（Too Many Requests）が発生したことを示しています。
  </Accordion>
</Accordions>

## 📦 データベースとアップグレードの問題

<Accordions>
  <Accordion title="アップグレード後にデータは失われますか？">
    データベースの種類によって異なります：

    - **MySQL**：データは失われません。
    - **SQLite**：デプロイコマンドに従ってボリュームをマウントし、`one-api.db`データベースファイルを永続化する必要があります。そうしないと、コンテナの再起動後にデータが失われます。
  </Accordion>

  <Accordion title="アップグレード前にデータベースを変更する必要がありますか？">
    通常は不要です。システムは初期化時に自動的に調整します。

    特別な処理が必要な場合は、更新ログに説明があり、対応するスクリプトが提供されます。
  </Accordion>

  <Accordion title="データベースを手動で変更した後のエラー：データベースの整合性が破損しています。管理者に連絡してください。">
    このエラーは、`ability`テーブルに無効なチャネルIDレコードが検出されたことを示しています。一般的な原因：

    - `channel`テーブルのレコードを削除する際に、`ability`テーブルの無効なチャネルが同期的にクリーンアップされなかった。
    - チャネルがサポートする各モデルには、`ability`テーブルに対応するレコードが必要です。
  </Accordion>
</Accordions>
